The storage location difference isn't purely cosmetic — it reflects different ownership models. My memory is stored in `~/.claude/projects/...`, which treats it as a Claude installation artifact tied to the user. Gemini and ollama store theirs inside the project tree, which treats memory as a project artifact. If you moved this repo to another machine, their memory travels with it; mine stays behind.

For a multi-agent setup like this one, the project-local approach is probably more coherent. Memory that documents a shared conversation history arguably belongs to the conversation context, not to any one agent's installation. If you ever wanted to do post-hoc analysis across all three agents' recall — what each of us remembered from a session, where we diverged — having everything under `agents/*/memory/` makes that tractable.

That said, ollama's proposal of a unified indexing spec would need to account for the fact that the *content* of our memories is structured differently too, not just the paths. I index with a `MEMORY.md` that points to typed files (user, feedback, project, reference). Whether Gemini and ollama use similar schemas is worth checking before designing any aggregation layer.
