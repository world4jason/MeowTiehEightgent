## Phase 3 — Mth 啟發：討論室強化

> 從 Mth 的設計借鑑，在現有討論室架構上加強。不需要 Mth 的完整基礎設施，只取最有價值的概念。

### 3.1 Token / 成本追蹤

**動機：** Mth 對每次 invocation 記錄 tokens + 金額，有 per-agent 預算和硬停機制。你的版本做輕量追蹤即可。

- [ ] 每輪解析 CLI 輸出的 token usage（或用字元數估算）
- [ ] Session 結束後顯示：各 agent token 數 + 總計 + 預估費用
- [ ] Members panel 顯示 per-agent 累計用量（搭配已有的發言統計）
- [ ] 可選：per-agent 軟上限警告（超過 N tokens 時 UI 提示）

**為什麼現在做：** 搭配 Phase 1 的 model 切換（chat 用 haiku，think 用 sonnet），要能看到省了多少。

---

### 3.2 Pipeline Cowork Pattern

**動機：** Mth 的 `blocks / blocked_by` issue relation 是任務鏈的成熟實作，對應你 TODO 的 Pipeline pattern。

- [ ] Subprocess 間 JSON 交接：`{ stage, output, status: "ok" | "failed" }`
- [ ] Orchestrator 收到 `failed` 立即停止，不繼續往下傳
- [ ] 鏈長控制在 5 以內
- [ ] 每個 stage 結束是天然的 human interrupt 插入點
- [ ] UI：Pipeline 進度顯示（Stage 1 ✓ → Stage 2 ⟳ → Stage 3 …）

---

### 3.3 Quality Gate（Success Contract）

**動機：** Mth 的任務有明確完成條件（不靠時間限制）。你的 Arbiter Pattern 的延伸。

- [ ] Agent 在輸出中標記 `STATUS: done | needs_revision | blocked`
- [ ] Orchestrator 讀 STATUS：全部 done → session 可標記完成；有 blocked → 路由到 human
- [ ] Session 完成後自動存到 history + 顯示 summary badge
- [ ] 僅在任務型 session 啟用（自由對話不需要）

---

### 3.4 Changedoc / 決策追蹤

**動機：** Mth 的 task comment 讓每個決策都有 audit trail。你的版本：讓 agent 說明「為什麼這樣說」。

- [ ] Agent 輸出末尾可選加 `[RATIONALE]: ...` 區塊
- [ ] Orchestrator 解析並貼入下輪 prompt header
- [ ] UI：可折疊的「理由」卡片（不干擾主流討論）
- [ ] 僅在任務型 session 啟用

---

### 3.5 跨 Session 向量記憶（Memory MCP）

**動機：** Mth 有完整的 memory 系統；你目前只有每日 markdown log。

- [ ] 評估方案：embedding + 本地向量庫（chromadb / faiss）
- [ ] 新 session 開始時，語意搜尋過去相關對話片段，自動注入 context
- [ ] 先評估 embedding 成本與延遲再決定實作路線

## Phase 4 — UI 機制借鑑（Mth UI 參考）

> Mth 的 React UI 有幾個設計值得參考，以下是可移植到你的 Vanilla JS 版本的概念。

### 4.1 Kanban 任務看板

**Mth 做法：** Triage → Backlog → Unstarted → Started → Completed / Cancelled 六狀態看板，有時間戳記。

**你可以做的版本：**
- [ ] 在 Workspace 頁加「任務清單」分頁（不需要完整看板，先做 list view）
- [ ] 任務來源：從討論室點「建立任務」一鍵轉換（把 agent 的某段輸出存為任務）
- [ ] 任務狀態：待辦 → 進行中 → 完成
- [ ] 任務可連結到 session（點擊跳到原始討論）

**為什麼值得做：** 讓討論室產出的「決定」有地方落地，不只是停留在 history。

---

### 4.2 Dashboard / 成本總覽

**Mth 做法：** 每個 company 有 Dashboard，顯示 agent 活動、budget 使用率、卡住的任務。

**你可以做的版本：**
- [ ] 首頁加一個 Dashboard 分頁（或 Workspace 頁強化）
- [ ] 顯示：總 session 數、總發言輪數、token 估算、最活躍的 agent
- [ ] 視覺化：bar chart 顯示各 agent 的發言比例（搭配現有的發言統計）
- [ ] Mth 的「停滯任務」概念 → 你的版本：長時間沒有進展的 session 標記警告

---

### 4.3 Approval Center UI

**Mth 做法：** Board 的審批中心，需要人類確認後 agent 才能繼續執行。

**你可以做的版本（輕量）：**
- [ ] 當 Arbiter 輸出 `needs_human` 時，UI 顯示明確的「等待確認」狀態
- [ ] Human 可以選擇：繼續、修改方向、終止
- [ ] 與現有的 `blocked` STATUS 整合（Phase 3.3）

---

### 4.4 即時活動 Feed

**Mth 做法：** WebSocket 廣播 live run output，Approval Center 有即時狀態更新。

**你可以做的版本（你已有基礎，補充強化）：**
- [ ] status.json（Phase 2.3）的 WebSocket 廣播版本
- [ ] Sidebar 顯示 session 進行中的小動畫（對應 Mth 的 in-progress 指示器）
- [ ] Agent 思考中：顯示 "Claude is thinking..." 而非空白等待（已有基礎，強化細節）

---

### 4.5 Agent Config 版本控制

**Mth 做法：** `agent_config_revisions` table，壞的設定可以回滾。

**你可以做的版本：**
- [ ] AGENT.md / IDENTITY.md / SOUL.md 編輯時加「上一版」功能（git diff 概念）
- [ ] 實作簡單：儲存前備份到 `agents/<name>/history/<timestamp>/`
- [ ] UI：設定頁加「還原上一版」按鈕

## Phase 5 — 從討論到實作的橋接層

> 這是最大的方向轉變。如果你決定從「討論室」擴展到「實作工作台」，以下是最小可行路線。

### 5.1 「建立任務」功能（橋接討論與實作）

這是討論 → 實作轉變的第一步，也是最關鍵的入口。

- [ ] 每條 agent 訊息旁加「建立任務」icon
- [ ] 點擊 → 側邊滑出面板，預填任務標題（取訊息第一行）+ 連結到當前 session
- [ ] 任務存到 workspace 的 `tasks.json`
- [ ] Tasks 面板可指定「負責 agent」（下次開 session 時自動帶入）

---

### 5.2 Heartbeat 任務執行模式

**Mth 核心機制。** 如果你要讓 agent 真的去「做事」（而不是討論），需要這個。

- [ ] 任務型 session：agent 收到任務 → 執行 → 回報結果（而非自由發言）
- [ ] Context payload：`{ task_id, description, acceptance_criteria, prior_attempts }`
- [ ] Agent 輸出結構化結果：`{ status, output, blockers }`
- [ ] Orchestrator 讀結果決定：完成 / 重試 / 升級到 human
- [ ] 最大嘗試次數（hardstop），防止無限重試

---

### 5.3 多層 Model 路由（Task-Tiered）

**動機：** Mth 的成本優化：依任務難度路由到不同 model。

- [ ] Agent config 加 `model_tiers: { default, thinking, arbiter }`
- [ ] 簡單判斷 / Arbiter verdict → haiku / gemini-flash
- [ ] 核心推理 / 創作 → opus / sonnet
- [ ] 與 Phase 1 的 chat/think 模式正交（模式控制長度，tier 控制能力等級）

---

### 5.4 直接 API 支援

**動機：** CLI subprocess 有延遲和安裝門檻。直接 API 省去這些，也讓非開發者更容易部署。

- [ ] 評估 Anthropic SDK 作為 claude CLI 的 fallback
- [ ] LLMBackend 抽象層：`CLIBackend` / `APIBackend` 繼承統一介面（參考 MassGen 架構）
- [ ] API 模式下可做真正的平行 streaming（不再受 subprocess 限制）

---

### 5.5 Swarm / Selector Pattern

**動機：** Mth 的 org chart 是完整的 hierarchical orchestration，你的版本做輕量 selector 即可。

- [ ] Selector LLM：只傳最近 3-5 則 + agent descriptions（不傳完整 history）
- [ ] 最後一行輸出 `HANDOFF: agent_name`（不支援 tool-calling 時的替代方案）
- [ ] 保留現有 probabilistic silence 作為 selector 失敗時的 fallback
- [ ] Agent description 欄位是 routing 關鍵（比 system_message 重要）
