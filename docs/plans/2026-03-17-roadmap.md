# MeowTiehEightgent — 功能 Roadmap

> 日期：2026-03-17
> 狀態：規劃中

---

## 高價值功能（優先做）

### 1. Streaming 輸出

**目標**：Agent 回應改為逐字打字顯示，而非一次送出整段文字。

**現況**：`build_prompt()` → CLI subprocess → 一次性回傳全文 → WebSocket 一次送出。

**改動**：
- **Backend**：`subprocess` 改用 `asyncio.create_subprocess_exec` + `stdout.readline()`，逐行 stream；WebSocket 改送 `{type: 'chunk', agent, text}` + 結尾送 `{type: 'message_end'}`
- **Frontend**：新增 `handleChunk()` — 找到對應 agent 的訊息泡泡，append text；`message_end` 時觸發 markdown render + duration 顯示
- **Ollama**：已是 HTTP streaming（`/api/generate` with `stream: true`），改用 `aiohttp` + async generator

**影響範圍**：`app.py` `run_agent()`、`websocket_endpoint()`、`index.html` `handleMessage()`

---

### 2. 圖片附件（Vision）

**目標**：Chat 輸入可附加圖片，傳給支援 vision 的 model（Claude、Gemini）。

**現況**：附件系統已有 FileReader 框架，只做文字檔。

**改動**：
- **Frontend**：
  - `handleChatAttach()` 判斷 `file.type.startsWith('image/')` → 讀成 base64 DataURL
  - chip 顯示縮圖預覽（`<img>` 40×40）
  - `buildMessageWithAttachments()` 對圖片改為傳 `{type: 'image_url', data: base64}` 格式
- **Backend**：
  - WebSocket `human` message 增加 `images: [{name, base64, mime}]` 欄位
  - `build_prompt()` 對支援 vision 的 model 組裝 multimodal content array
  - Claude：`content: [{type:'image', source:{type:'base64',...}}, {type:'text',...}]`
  - Gemini：`parts: [{inlineData:{mimeType, data}}, {text}]`

**前提**：需確認使用的 CLI 工具支援 vision（claude / gemini CLI 都支援）

---

### 3. @filename 語法

**目標**：對話中輸入 `@guide.md` → 把 workspace 檔案全文注入當輪 context。

**現況**：`@AgentName` 已實作。`@filename` 的 backend resolve 邏輯尚無。

**改動**：
- **Backend** `resolve_human_text()`：
  - regex 抓 `@[\w\.\-]+\.\w+`（有副檔名 = 檔案）
  - 查 `workspaces/<workspace_id>/files/<filename>`
  - 找到 → prepend 到 `history_entry`：`[File: guide.md]\n\`\`\`\n{content}\n\`\`\``
  - 找不到 → 原樣保留
- **Frontend** `onMsgInput()`：
  - `@` 後接有 `.` 的字串 → 改顯示 file picker（從 workspace files 列表）
  - 目前 `@` → agent picker，需要分叉判斷

**注意**：需要 WebSocket start message 帶 workspace_id 讓 backend 知道查哪個 workspace（已有）

---

### 4. Session 搜尋

**目標**：sidebar 加搜尋框，即時 filter session 標題。

**改動**：
- **Frontend only**：
  - `#session-list` 上方加 `<input id="session-search">`（focus 時展開，失焦縮回）
  - `loadSessions()` 完成後，search input 的 `oninput` 事件 filter `.session-item` 的 display
  - workspace folder 若全部 session 被 filter 掉 → 也隱藏該 folder
- **CSS**：搜尋框 sticky top of `#session-list`

---

### 5. Agent 發言統計

**目標**：session 結束後（或進行中）顯示各 agent 的發言輪數與大約 token 數。

**改動**：
- **Frontend**：在 `#chat-header` 或 members panel 加 stats badge
  - 監聽每個 `message` event，累計 `{agent: count}` map
  - 顯示：`Claude ×5  Gemini ×3`
- **Backend**（可選）：`messages.json` 已存所有訊息，`GET /sessions/{id}` 可計算後回傳

## 中等複雜（次優先）

### 6. Workspace 預設 Agents

**目標**：workspace 有 `default_agents` 欄位，開新 session 時自動勾選。

**現況**：`config.json` 已有 `default_agents` 欄位，但 workspace 設定頁沒有 UI 可以編輯它。

**改動**：
- **Frontend** workspace detail panel 加 `Default Agents` section
  - 顯示 checkbox list（從 agentData 取）
  - 存到 config.json 的 `default_agents`
- `selectWorkspace()` 已有「apply default agents」邏輯，不用改

---

### 7. Message 複製按鈕

**目標**：hover 在 agent 訊息上顯示複製 icon，點擊複製純文字（無 markdown）。

**改動**：Frontend only
- `.msg-body` 加 relative + hover 顯示 copy btn（右上角）
- `navigator.clipboard.writeText(rawText)`
- 複製成功 → btn 短暫顯示 ✓

---

### 8. Session 重命名

**目標**：雙擊 sidebar session 名稱可 inline 編輯。

**現況**：session 標題存在 messages.json 的第一個 system message（`Topic: xxx`）。

**改動**：
- **Backend**：新增 `PUT /sessions/{id}/topic` → 找第一個 system message，replace Topic
- **Frontend**：sidebar session item 雙擊 → `<input>` inline edit → blur/Enter 送出

---

### 9. Export to Markdown / PDF

**目標**：下載按鈕（現有）改為支援 Markdown 格式；PDF 用 print API。

**現況**：`downloadSession()` 已有 HTML print window，但排版是臨時做的。

**改動**：
- 下載按鈕改為 dropdown：`Markdown` / `PDF`
- Markdown：`[Agent] text\n\n` 拼接，`Blob` download
- PDF：現有 print window 改良 CSS

---

### 10. Ollama HTTP 整合

**目標**：直接 HTTP call Ollama（`/api/generate` 或 `/api/chat`），不經 CLI。

**現況**：Ollama 走 CLI subprocess（`ollama run <model>`），無 streaming。

**改動**：
- **Backend** `run_agent()`：判斷 model type = `ollama`
  - `aiohttp.post('http://localhost:11434/api/chat', json={model, messages, stream:True})`
  - Async stream → WebSocket chunk
- **Model 設定頁**：type 選 `ollama` 時顯示 `model name` 欄位（e.g. `llama3.2`）
- **好處**：streaming 免費送、不需要 ollama CLI installed in PATH

## 實作順序建議

```
Phase A（本週）
  1. Streaming 輸出        ← 體驗提升最大
  2. Session 搜尋          ← 純前端，快
  3. Message 複製按鈕      ← 純前端，快

Phase B
  4. Ollama HTTP 整合      ← streaming 框架完成後順帶做
  5. @filename 語法        ← backend 小改
  6. Workspace 預設 Agents ← 已有欄位，補 UI

Phase C
  7. 圖片附件（Vision）    ← 需測試各 CLI 的 multimodal API
  8. Session 重命名        ← backend 需新 endpoint
  9. Agent 發言統計        ← 純前端
  10. Export Markdown/PDF  ← 改良現有功能
```
