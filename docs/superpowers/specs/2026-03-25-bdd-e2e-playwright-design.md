# BDD E2E Testing Design — Playwright + Gherkin Full Coverage

Generated by brainstorming + CEO review on 2026-03-25
Branch: main | Mode: SELECTIVE EXPANSION (6/6 cherry-picks accepted)

## Problem Statement

MeowTiehEightgent 有 698 個 unit/integration tests（515 server + 183 UI），但 E2E 層幾乎為零 — 只有 3 個 Playwright smoke spec（15 個 test cases），且指向已退役的 Python port 8000。

v0.10.0 引入大量跨模式功能（pause/resume、intent router、event bus、room goal），手動 QA 無法可靠覆蓋 regression。需要一套完整的 BDD E2E 測試，通過 UI 實際操作驗證所有服務情境。

## Decisions Summary

| 決策 | 選擇 | 理由 |
|------|------|------|
| Scope | 全覆蓋（Chat + Cowork + Settings + cross-mode） | 產品複雜度需要 |
| BDD 框架 | Gherkin `.feature` + `playwright-bdd` | 正統 BDD、living documentation、step reuse |
| 測試資料 | Seed + Teardown via API（TestFactory） | 每個 scenario 獨立、可平行 |
| 服務啟動 | Playwright 自動啟動雙服務（server:3100 + UI:5173） | 一鍵 `pnpm test:e2e`，CI 自動起 |
| 粒度 | Happy path + 關鍵 edge cases（~80-120 scenarios） | 務實平衡 |
| 組織架構 | 按模式分層 + cross-mode | 對齊 UI ModeToggle 結構 |

## Auth & Test Harness

The app uses `better-auth` for authentication. E2E tests handle auth via:

1. **`storageState` approach** — A global setup step logs in once via API (`POST /auth/sign-in`), saves the cookie/token to `e2e/.auth/user.json`, and all tests reuse this state via `storageState` in Playwright config.
2. **Test user** — A dedicated test user is seeded in global setup: `test@meowtieh.local` / `test-password-e2e`. This user has full access to all modes.
3. **`Given I am logged in`** — This step verifies `storageState` is loaded (no-op if already authenticated). If auth is not available (e.g., auth disabled in dev mode), the step is a no-op.

## LLM Mock Strategy

E2E tests **must not** call real LLM providers. The server supports a `TEST_MODE=true` environment variable that:

1. **Replaces CLI subprocess calls** with a mock agent that returns canned responses from `e2e/fixtures/mock-responses/`.
2. **Mock responses are deterministic** — each mock file maps to a scenario tag (e.g., `@mock:suggest-issue` → returns response containing `[SUGGEST_ISSUE]` marker).
3. **Streaming simulation** — mock agent outputs chunks with 50ms delay to simulate real streaming behavior.
4. **WebSocket events** — mock agent emits real WS events (`agent:status`, `agent:intent`) so UI tests verify real event handling.

```typescript
// Server-side: when TEST_MODE=true
// Instead of spawning `claude --print ...`, use MockAgent
class MockAgent {
  async stream(prompt: string, tag?: string): AsyncIterable<string> {
    const fixture = loadFixture(tag || 'default');
    for (const chunk of fixture.chunks) {
      yield chunk;
      await sleep(50);
    }
  }
}
```

This approach tests the full UI→WS→Server pipeline while keeping LLM responses deterministic.

### Execution Flow

```
pnpm test:e2e
  → global-setup.ts: pg_isready + health checks
  → playwright-bdd: parse .feature → generate .spec.ts
  → 3 workers (chat / cowork / settings) × 3 viewports
  → per-scenario: TestFactory.seed() → browser actions → assertions → TestFactory.teardown()
  → on failure: screenshot + trace capture
  → axe-core a11y check on key pages
  → HTML report output
```

## Test Data Factory

```typescript
// e2e/support/fixtures.ts
interface TestFactory {
  // Unique prefix per worker for parallel isolation
  prefix: string; // e.g. "test-worker0-1711234567"

  // Chat data
  createSession(opts?: {
    agent?: string;
    withMessages?: number;
    withGoal?: string;
  }): Promise<{ id: string; title: string }>;

  createAgent(opts?: {
    name?: string;
    emoji?: string;
    color?: string;
    skills?: string[];
    model?: string;
  }): Promise<{ name: string }>;

  // Cowork data
  createIssue(opts?: {
    title?: string;
    projectId?: string;
    status?: string;
  }): Promise<{ id: string; title: string }>;

  createProject(opts?: {
    name?: string;
    budget?: number;
  }): Promise<{ id: string; name: string }>;

  createGoal(opts?: {
    title?: string;
  }): Promise<{ id: string }>;

  // Settings data
  createModel(opts?: {
    name?: string;
    type?: 'cli' | 'api' | 'ollama';
  }): Promise<{ name: string }>;

  createWorkspace(opts?: {
    name?: string;
    systemPrompt?: string;
    defaultAgents?: string[];
  }): Promise<{ id: string; name: string }>;

  createSkill(opts?: {
    name?: string;
  }): Promise<{ slug: string }>;

  // Cleanup — batch delete all data with this.prefix
  teardownAll(): Promise<void>;
}
```

All created entities use `${prefix}-${name}` naming for isolation.

**Teardown strategy:** `teardownAll()` iterates over internally tracked entity IDs (factory records every created entity's ID) and issues individual DELETE calls, ignoring 404s. No pattern-based bulk delete needed — the factory tracks what it created.

Additionally, a dedicated `POST /api/test/cleanup` endpoint (guarded by `NODE_ENV=test`) is available as fallback for orphan cleanup by prefix match.

## Error Handling & Resilience

### Global Setup Pre-checks
| Check | Action on Failure |
|-------|-------------------|
| `pg_isready` | Clear error: "Start PostgreSQL first" |
| Server health `/api/health` | Playwright webServer auto-starts — timeout = fail |
| UI health `localhost:5173` | Playwright webServer auto-starts — timeout = fail |

### Test Data Isolation
- TestFactory uses `test-{worker}-{timestamp}` prefix
- `teardownAll()` batch DELETEs by prefix, ignores 404
- No shared state between scenarios or workers

### Flaky Test Mitigation
- `retries: 2` in Playwright config
- Screenshot + trace on first retry
- No `waitForTimeout()` — use `waitForSelector()` / `expect().toBeVisible()`
