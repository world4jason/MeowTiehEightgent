### 2. Pre-Compaction Memory Flush（v0.11.0 核心功能）

**三層記憶架構：**
- Layer 1: Working Memory — session history + kanban（即時）
- Layer 2: Session Memory — summary.json（壓縮後）
- Layer 3: Long-Term Memory — facts + entities（跨 session）

**雙時機觸發：**
- Pre-compaction（壓縮前）— regex heuristic，零 LLM 成本，< 10ms
- Post-session（session 結束後）— LLM 3-stage distillation，背景執行

**Distillation Pipeline：**（借鏡 OpenClaw Memory Stack 0.5.7 `distill.sh`）
1. Triage — LLM 評分 1-10，低分跳過（heuristic fallback）
2. Fact Extraction — LLM 抽取 8 種 fact 類型，importance ≥ 4 過濾
3. Entity Extraction — LLM 抽取 {entity: description}，JSON merge
4. Store — 寫入 `memory/YYYY-MM-DD.md` + `entities.json`

**防禦機制：**
- Semaphore(3) — 最多 3 個同時 distillation
- Timeout(60s) — 防 LLM hang
- Session dedup — 同 session 不重複蒸餾
- 全路徑 try/except — 失敗靜默降級
- Structured logging — triage score, facts count, duration

### 3. Memory Injection

`build_prompt()` 新增注入：
- `## Recent Memory` — importance-weighted facts，500 char budget，read-time dedup
- `## Known Entities` — entities.json，300 char budget

### 4. append_memory 路徑分離

## Graph RAG 調研（Phase 4 候選方案）

目前 Meow 的 entity extraction 是 flat dict（`{name: description}`），不保留實體之間的關係。Graph RAG 可以補強這一點。以下是調研的方案：

### 方案比較

| 方案 | Stars | 特色 | 複雜度 | 適合 Meow？ |
|------|-------|------|--------|------------|
| **Microsoft GraphRAG** | 25K+ | 完整：entity + relationship + community detection + summarization | 極高（indexing 很貴） | ❌ 太重 |
| **fast-graphrag** | 3K+ | 6x 成本節省 vs GraphRAG，PageRank 檢索，incremental update | 中 | ⭐ 最適合 |
| **LightRAG** | 30K+ | EMNLP2025 獲獎，4 種查詢模式（naive/local/global/hybrid），多種 backend | 中 | ⭐ 備選 |
| **nano-graphrag** | — | 1100 行重寫 GraphRAG，最輕量 | 低 | ⭐ 入門選擇 |
| **Graph RAG Lite** | 概念 | 只做 entity+relationship extraction（跳過 community/summarization），用 LangChain LLMGraphTransformer | 低-中 | ⭐ 最小改動 |
| **cognee** | 14K+ | 「6 行程式碼」知識引擎，Neo4j + 向量混合 | 中 | 可選 |
| **nocturne_memory** | 849 | MCP agent 記憶，graph backend + tree frontend，visual dashboard，rollback | 中 | 概念參考 |

### 各方案詳細分析

**fast-graphrag（推薦第一候選）**
- 自動 entity/relationship extraction → 建構知識圖譜
- 用 personalized PageRank 做 retrieval（不只 cosine similarity）
- 支援 incremental update（不用 full reprocessing）
- 比 GraphRAG 便宜 6x
- 全 async + typed

**LightRAG（推薦備選）**
- 4 種查詢模式：Naive（純向量）、Local（entity 鄰居）、Global（community 摘要）、Hybrid
- 多種 storage backend：NetworkX/Neo4j（圖）、FAISS/Chroma/Milvus（向量）
- 需要 32B+ 參數的 model 做 extraction（成本考量）

**nano-graphrag（最輕量入門）**
- 只有 1100 行 code
- 核心跟 GraphRAG 一樣但大幅簡化
- 支援 incremental update（MD5 去重）
- 雙 model tier：貴 model 做 planning，便宜 model 做 summarization

**Graph RAG Lite（最小改動）**
- 跳過 community detection 和 report generation
- 只做 entity+relationship extraction → Neo4j
- 用 LangChain `LLMGraphTransformer` 做 extraction
- 搭配 hybrid retrieval（向量 + keyword + Cypher 圖查詢）
- 最接近我們現在的做法，改動最小

**nocturne_memory（概念參考）**
- 「第一人稱主權記憶」— agent 主動決定記什麼（vs 系統自動抓）
- Graph backend + Tree frontend（路徑式存取 `core://agent/identity`）
- 有 visual dashboard + human-in-the-loop 審核
- Disclosure triggers — 條件式記憶召回（「當用戶提到 X 時，想起 Y」）
- 概念跟 Meow 的 SOUL.md / IDENTITY.md / AGENT.md 體系很接近

### 對 Meow 的整合路徑

```
Phase 4a: 用 nano-graphrag 或 Graph RAG Lite 做 PoC
  - 把現有的 _llm_extract_entities() 替換為 graph transformer
  - 實體 + 關係存入簡單圖結構（NetworkX or SQLite）
  - Retrieval 從 grep 升級為圖遍歷

Phase 4b: 如果效果好，升級到 fast-graphrag
  - PageRank retrieval
  - Incremental update
  - 持久化圖

Phase 4c: 如果需要更強，考慮 LightRAG
  - 4 種查詢模式
  - Community detection
```

### 為什麼現在不做

1. 目前記憶量小（幾天的 facts + entities），grep 夠用
2. 加 graph DB 是第一個非檔案系統依賴，要慎重
3. 先觀察 flat entity extraction 的品質，再決定是否需要關係
4. CTO review 明確建議先跑 file-based 系統
