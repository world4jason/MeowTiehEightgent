# Devlog — 2026-03-17

## What was built

### Architecture redesign: Models + Agents

Split the old flat `agents` config section into two layers:

- **Models** (`config.json → models`) — LLM connection configs. Two types: `cli` (subprocess) and `api` (Ollama HTTP).
- **Agents** (`agents/<name>/config.json`) — Personas. Each references a model by ID. Multiple agents can share one model.

This makes "two personas both running Claude" natural and explicit.

Each agent folder now owns:
- `config.json` — emoji, color, description, model ref, skills, enabled flag
- `AGENT.md` — main operational instructions, injected into every prompt
- `IDENTITY.md`, `SOUL.md` — character and values
- `MEMORY.md`, `memory/` — persistent memory

`agents/_default/` is a template folder. New agents are created by copying it with `{name}` substituted.

Migration (`migrate_if_needed`) runs at startup and converts old configs transparently.

### Settings UI

Full-page settings overlay, two-panel layout:

- **模型** — model CRUD with connection testing
- **代理人** — agent CRUD + inline AGENT.md / IDENTITY.md / SOUL.md editors
- **技能** — skill browser, create, zip upload
- **關於你** — edit `_default` templates
- **關於我** — edit `USER.md`

### Skills system

- Auto-detects `SKILL.md` and `SKILLS.md` (both accepted)
- Flags dirs missing a skill file with an amber warning card
- `POST /skills` — create from form
- `POST /skills/upload` — extract from zip

### Ollama pull UI

In the Ollama model config card:
- Dropdown lists locally installed models (refreshable)
- Pull section loads cloud-available models from `?cloud=true`
- SSE progress stream from `POST /providers/ollama/pull` feeds a live progress bar

### Session export

Click ⬇ on any sidebar session → format picker → Markdown, JSON, or PDF (browser print).

### Resume fix

When resuming a session, the first human message was ignored by the first agent because the conversation loop started before the `human` WS message arrived. Fixed by draining the first human message from the event queue after loading history and prepending it to `history_text`.

### Stop responsiveness

Stop had up to 2s delay in auto mode. Missing `break` after `running = False` in the between-turn event wait. Added.

## Round 2 (evening)

### ConversationEngine

Extracted turn-scheduling logic into `conversation_engine.py` (independent, no FastAPI dependency).

Features:
- **Round-robin base order** — same as before (`itertools.cycle` replaced)
- **@ mention** — `@AgentName` in human message jumps that agent to front; rest of current round drops; next cycle starts with that agent; cycle after returns to base order
- **Probabilistic silence** — opt-in toggle at session start (`silence: true`). Formula: `base = min(0.35, (N-2)/N * 0.5)`; consecutive passes halve pass probability so no agent stays silent forever
- **Spoke-alone penalty** — if only one agent spoke in a full cycle, that agent's pass probability increases by +20% per round (capped at +60%), preventing monopolization

`app.py` wires `ConversationEngine` at session start and routes human messages through `extract_mention()` / `on_mention()` / `on_human()`.

### Session folder structure

Migrated from flat `history/<session_id>.json` to:
```
history/<session_id>/
  messages.json
  workspace/        ← placeholder for future agent working directory
```

`migrate_history_to_folders()` runs at startup (idempotent). `list_sessions()` now iterates directories. Existing tests pass unchanged (tmp_path fixture auto-creates folder structure).

### Marketplace install with name override

Install modal now shows editable **name** and **model** fields (instead of just model). Allows installing the same marketplace template multiple times under different names (different LLM configurations). Backend uses `body.get("name") or agent_id` as destination folder.

### 409 duplicate name handling

`submitAddPersona()` and `installMarketAgent()` both catch HTTP 409 and show a user-friendly message ("「X」已存在！請換一個名稱再建立。") instead of silently failing. Name input gets focus.
