## Phase 0.2 — History Sliding Window

**目標**：防止 `history_text` 無限成長導致 agent context window 溢出。

### 實作重點

- 新增 `TRUNCATION_MARKER = "[... 較早對話已省略 ...]\n\n"`
- 新增 `truncate_history(history_text, max_chars)` — 用 `re.split(r'(?=\n\[[\w\s\-]+\]: )')` 切開各輪次，從最舊端移除直到符合長度，插入截斷標記
- WS handler 每輪 `build_prompt()` 前：讀 `load_config().get("max_history_chars", 80000)` 並計算 `_trimmed_history`
- `history_text` 本身繼續累積（完整記錄），只有送給 agent 的 copy 被截斷

## Phase 0.4 — Protected Paths

**目標**：防止路徑遍歷攻擊與系統檔案被覆寫。

### 實作重點

- 新增 `PROTECTED_FILENAMES` frozenset：`guide.md`、`config.json`、`.env`、`requirements.txt`
- 新增 `validate_filename(filename, *, allow_protected=False)` — 檢查：非空、長度 ≤ 255、無 `/` `\`、無 `..`、符合 `^[\w\-. ]+$` 白名單、非受保護檔名
- 新增 `safe_workspace_path(workspace_dir, filename)` — `os.path.realpath()` 確認路徑在 workspace 內（防禦縱深，應對 symlink attack）
- `upload_workspace_file()` 端點加入 validation，違規回傳 `403 Forbidden`

### 測試 (TDD)

新增 `TestProtectedPaths`（18 tests）：
- 12 個 `validate_filename()` unit tests（正常/各種攻擊向量）
- 2 個 `safe_workspace_path()` unit tests（正常路徑/symlink traversal）
- 4 個 integration tests（valid upload / path traversal / protected / invalid char）

全部 PASS。

## Bug Fixes（同日）

- **Instructions 編輯按鈕無效**：`onclick="openInstructionsModal('${wsId}', ${JSON.stringify(...)})"` 中 `JSON.stringify` 產出雙引號，終止 HTML attribute。改為 function 直接從 `workspaceData` 讀取，不嵌入 onclick。

## Gemini 啟動逾時修復 + Agent 測試按鈕

**問題根因**：Gemini CLI 在產生第一行 stdout 之前會初始化 MCP context（讀取 credentials、memory files），即使是簡短 prompt 也需要 7–8 秒。原 `startup_timeout_seconds = 10` 在生產環境下（含 AGENT.md + workspace context）觸發 `SubprocessStartupError`。

### 修正

- `DEFAULT_MODELS["gemini"]["startup_timeout_seconds"]`：`10` → `30`（加上注解說明原因）

### Agent 測試按鈕（設定頁）

- 後端：`POST /agents/{name}/test` 端點（已存在）— 呼叫 `call_agent()` with simple ping prompt，30s timeout，回傳 `{ok, response/error}`
- 前端：
  - 新增 `.model-test-btn` CSS（outline 綠色調）
  - 在 Persona 設定頁 save-bar 加入「測試連線」按鈕（`testAgent()` JS function）
  - 結果顯示在按鈕下方 `#pcfg-test-result`：成功綠底、失敗紅底

### 測試（TDD）

新增 2 tests（`TestAgents`）：
- `test_agent_test_endpoint_unknown_agent` — 未知 agent 回 `{ok: false, error: "Unknown agent"}`
- `test_agent_test_endpoint_ok` — 以 `echo` CLI model 驗證端點回 `{ok: true, response: ...}`
