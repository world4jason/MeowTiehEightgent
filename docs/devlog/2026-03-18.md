## Phase 0.1 實作（2026-03-19 凌晨完成）

### Spec 設計

採用 v2 spec（Spec Review 後修訂），相較 v1 有三大變化：

1. **Idle Timeout 取代 Total Timeout**：claude 合法思考可超過 60 秒，但「完全無動靜」才是問題，idle timeout 更精準。startup timeout 獨立設定（10s），偵測啟動失敗。
2. **Typed Exception 三層架構**：`SubprocessError` → `SubprocessStartupError` / `SubprocessTimeoutError` / `SubprocessCrashError`，WS handler 只需 catch base class，同時保留足夠的錯誤分類給前端 badge 使用。
3. **Partial Output Contract**：`partial_output` 欄位明確規定：`SubprocessStartupError` 時為空字串（無 chunk 送出），`SubprocessTimeoutError` / `SubprocessCrashError` 時可能有內容（已透過 chunk WS event 送出，不重複傳）。這讓 WS handler 的 `agent_error` event 的 `partial_text` 規則清晰且不重複。

### 關鍵設計決策

| 決策 | 理由 |
|------|------|
| `partial_output` contract 明確化 | 避免 WS handler 與前端對「有沒有 chunk 被送出」各自猜測，造成重複顯示或遺漏 |
| NDJSON 延後到 Phase 4 | 目前純文字輸出，agent output 格式不統一，強上 NDJSON parsing 會讓 partial output 處理更複雜；Phase 4 統一 output schema 時再處理 |
| codex timeout 設 120s / 20s | codex 啟動慢（需拉 context）、思考長（code generation），通用 60s/10s 不夠；agent-level config 覆蓋 |
| 補完 hint 在 `build_prompt()` 清 flag | 確保 flag 只影響「下一個成功送出 prompt 的輪次」，不跨多輪累積 |

### 測試修復

**問題：** `AsyncMock(side_effect=lambda n: aio.sleep(999))` 在 Python 3.14 不會掛起，導致 startup timeout 測試無效（`wait_for` 立即完成）。

**原因：** `AsyncMock` 在新版 Python 會立即 evaluate `side_effect` 的 return value，`aio.sleep(999)` 是一個 coroutine object，但沒有被 await，因此 mock 立刻返回 `None`。

**修法：** 改用真正的 `async def` 函數作為 side_effect：
```python
async def _hang(n):
    await asyncio.sleep(999)

mock_read.side_effect = _hang
```
這樣 `AsyncMock` 會正確 await 該函數，`wait_for` 才能正常觸發 timeout。
