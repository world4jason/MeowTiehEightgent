## Backend Merge — Two Backends → One (Complete)

合併 Python FastAPI Chat 後端 (:8000) 和 Node.js Mth Cowork 後端 (:3100) 為單一 Node.js server。全程走完 brainstorming → spec → stakeholder review (PM/CEO/CTO) → eng review → subagent-driven TDD。

### 為什麼合併

- 維護兩套 backend 成本高
- Agent 無法跨後端工作（Chat agent 不能操作 Cowork issue）
- Settings 分散在兩個 API
- 目標：一個 agent 身份、兩個 runtime context、一個 server

### 設計決策（Brainstorm QA 7 輪）

| # | 決策 | 結論 |
|---|------|------|
| D1 | 合併方向 | Node 吃 Python，strangler fig 分階段 |
| D2 | Storage 分界 | Config/指令/memory/skills/chat history = file。Runtime = DB + daily export |
| D3 | Agent 身份 | `agents/{UUID}-{name}/`，一個 agent 兩個 context |
| D4 | Agent config | 統一規格，file 是 source of truth，DB 是 sync cache |
| D5 | Models → Adapter Presets | 拆「怎麼連」和「用什麼 model」，global preset + per-agent override |
| D6 | Company | file-based（config.json），單一 default company |
| D7 | Daily export | DB runtime 資料每天匯出 JSONL（Plan C，未實作） |

### 實戰 Gotchas（03-25 必讀）

踩過的坑，下次改 Chat 模組前務必知道：

1. **`process.cwd()` 在 server/ 裡是 `server/`，不是 project root。** 所有需要讀 `agents/`、`config.json`、`history/` 的地方都用 `resolve(process.cwd(), "..")`。已經在 `index.ts` 統一用 `chatProjectRoot` 傳進去。

2. **SPA fallback 會吃掉 `/chat/api/*` routes。** Mth 的 `app.ts` 有 `app.get(/.*/)` catch-all 返回 index.html。Chat routes 必須在 `createApp()` 裡、SPA fallback 之前掛載。不能在 `index.ts` 裡後掛。

3. **兩個 WS handler 共用一個 HTTP server。** Node.js `server.on("upgrade")` 會通知所有 listener。`/chat/ws` handler return 後，live-events handler 仍會被觸發並 `socket.destroy()`。修法：live-events handler 加了 `if (url.pathname.startsWith("/chat/")) return;` 跳過。

4. **Claude CLI `--output-format stream-json` 的 JSON 格式。** text 在 `{"type":"assistant","message":{"content":[{"type":"text","text":"..."}]}}` 裡面，不是直接在 `content` 上。參考 Mth 的 `packages/adapters/claude-local/src/server/parse.ts` 的 `parseClaudeStreamJson()`。

5. **Port 衝突。** Mth server 如果 3100 被佔，會自動跳到 3101、3102...。Vite proxy 寫死 `target: "http://localhost:3100"`，如果 port 跳了 proxy 會斷。開發時確保 3100 沒被佔。

6. **Migration 0044 的 schema drift。** `instance_settings.general` column 在之前就已存在但沒有 migration record。0044 migration 會報 `column already exists`。已用 `IF NOT EXISTS` wrapper 修。

7. **`config.json` 是 gitignored 的。** 跑完 `migrate_to_v1.py` 後 config.json 改成 adapter_presets 格式，但不會被 git 追蹤。新環境要手動跑 migration 或從備份還原。

### 設計脈絡（03-25 理解決策用）

- **使用者堅持 file-first。** DB agents table 是過渡期 sync cache，長期目標是移除。OpenClaw 已驗證純 file 架構可行。
- **PM 建議的「Phase 1 只做 agent 能去 Mth 工作」被否決。** 使用者認為那不是合併，直接要求 Phase 1 就開始搬 Chat。
- **stream-agent 原本要獨立重寫，eng review 後改為包裝 Mth adapter。** 避免重複實作 subprocess management。但最終 Chat WS 仍用自己的 `streamCliAgent`（比 Mth adapter 簡單，不需要 session codec/skill sync），只是參考了 Mth 的 parse 邏輯。
- **兩個 "agent" 概念共存。** Chat agent = 聊天人格（file-based）。Mth agent = 自主工作者（DB-based）。共享 `agents/{uuid}/` 的 config 和指令，但 runtime state 各自管理。
