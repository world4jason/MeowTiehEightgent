# Phase 0.3 — 圖片 --add-file 相容性設計規格

> 撰寫日期：2026-03-19
> 版本：v1
> 狀態：待實作
> 關聯 ROADMAP：Phase 0.3

---

## 問題描述

目前 `stream_cli_agent()` 在使用者上傳圖片時，對所有 agent 一律注入 `--add-file {image_path}` 參數。然而各 CLI agent 對圖片輸入的支援程度不同：

| Agent | CLI 圖片支援 | 目前行為 |
|-------|------------|---------|
| `claude` | 支援（`--add-file`） | 正常 |
| `gemini` | 支援（`--add-file` 或類似旗標） | 正常 |
| `codex` | **不支援** | 傳入 `--add-file` 導致 subprocess crash 或被忽略，產生 `SubprocessCrashError` |

此問題在 Phase 0.1 前因無錯誤回報機制而靜默失敗，Phase 0.1 後會觸發 `agent_error` badge——但根本原因未修。正確做法是在 agent 層宣告能力，並在 image injection 前檢查。

---

## 設計目標

1. **不傳錯參數**：對不支援圖片的 agent，完全跳過 `--add-file` 注入，不改變其他行為
2. **能力宣告在 config**：每個 agent 或 model 在 config 中明確說明是否支援圖片
3. **新增 agent 時預設安全**：`supports_image` 預設為 `true`（現有 claude/gemini 行為不變），新增不支援的 agent 時須明確設 `false`
4. **不改前端**：前端不需感知哪個 agent 支援圖片，錯誤訊息已由 Phase 0.1 badge 覆蓋

---

## 實作細節

### Config Schema 更新

**`config.json`（model 層，預設值）：**

```json
{
  "claude": {
    "type": "cli",
    "cmd": ["claude", "--print"],
    "supports_image": true,
    "idle_timeout_seconds": 60,
    "startup_timeout_seconds": 10
  },
  "gemini": {
    "type": "cli",
    "cmd": ["gemini"],
    "supports_image": true,
    "idle_timeout_seconds": 60,
    "startup_timeout_seconds": 10
  },
  "codex": {
    "type": "cli",
    "cmd": ["codex"],
    "supports_image": false,
    "idle_timeout_seconds": 120,
    "startup_timeout_seconds": 20
  }
}
```

**`agents/<name>/config.json`（agent 層，可覆蓋 model 預設）：**

```json
{
  "supports_image": false
}
```

### `DEFAULT_MODELS` 更新

在 `app.py` 的 `DEFAULT_MODELS` dict 中補上 `supports_image` 欄位：

```python
DEFAULT_MODELS = {
    "claude": {
        "cmd": ["claude", "--print"],
        "supports_image": True,
        "idle_timeout_seconds": 60,
        "startup_timeout_seconds": 10,
    },
    "gemini": {
        "cmd": ["gemini"],
        "supports_image": True,
        "idle_timeout_seconds": 60,
        "startup_timeout_seconds": 10,
    },
    "codex": {
        "cmd": ["codex"],
        "supports_image": False,
        "idle_timeout_seconds": 120,
        "startup_timeout_seconds": 20,
    },
}
```

### `_resolve_supports_image()` Helper

新增 helper，優先順序與 `_resolve_timeout()` 一致：

```python
def _resolve_supports_image(agent: dict) -> bool:
    """
    優先序：agent-level config > model_config > hardcode 預設（True）
    """
    if "supports_image" in agent:
        return bool(agent["supports_image"])
    model_cfg = get_model_config(agent.get("model", ""))
    if model_cfg and "supports_image" in model_cfg:
        return bool(model_cfg["supports_image"])
    return True  # 預設支援，避免誤封鎖新 model
```

### Image Injection 修改

在 `stream_cli_agent()`（或 `write_temp_images()` 的呼叫點）檢查 `supports_image`：

**修改前：**
```python
extra_args = []
if images:
    for img_path in write_temp_images(images):
        extra_args += ["--add-file", img_path]
```

**修改後：**
```python
extra_args = []
if images and _resolve_supports_image(agent):
    for img_path in write_temp_images(images):
        extra_args += ["--add-file", img_path]
```

若 `supports_image=False`，`images` 直接忽略，不呼叫 `write_temp_images()`，不建立暫存檔，不追加 `--add-file`。

### `write_temp_images()` 本身不需修改

檢查點在呼叫前即可，`write_temp_images()` 保持單純的「將 image bytes 寫入暫存檔並回傳路徑」邏輯。

## Config 更新摘要

| 位置 | 新增欄位 | 型別 | 預設值 |
|------|---------|------|--------|
| `config.json` model 層 | `supports_image` | bool | `true` |
| `agents/<name>/config.json` agent 層 | `supports_image` | bool | （繼承 model 層） |
| `DEFAULT_MODELS`（程式碼） | `supports_image` | bool | `True`（claude/gemini）、`False`（codex） |

## 測試計畫（TDD）

### Unit Tests（`_resolve_supports_image()`）

| 測試 | 情境 | 預期 |
|------|------|------|
| agent-level 設 False | `agent["supports_image"] = False` | 回傳 `False` |
| agent-level 設 True 覆蓋 model 預設 False | agent config `True`、model config `False` | 回傳 `True` |
| 僅 model-level 設定 | agent 無欄位、model config `False` | 回傳 `False` |
| 兩層都無設定 | agent 和 model config 都無 `supports_image` | 回傳 `True`（hardcode 預設） |
| codex DEFAULT_MODELS | `get_model_config("codex")["supports_image"]` | `False` |

### Unit Tests（`stream_cli_agent()` image injection）

| 測試 | 情境 | 預期 |
|------|------|------|
| 不支援圖片時跳過 | `supports_image=False`、傳入非空 `images` | `--add-file` 不在 `proc` 的 `args` 中；`write_temp_images` 不被呼叫 |
| 支援圖片時注入 | `supports_image=True`、傳入非空 `images` | `--add-file {path}` 出現在 `proc` 的 `args` |
| 無圖片時不注入 | `images=None` 或 `images=[]` | `--add-file` 不在 args（無論 `supports_image`） |

### Integration Tests

| 測試 | 情境 | 預期 |
|------|------|------|
| codex 收到圖片不 crash | WS 傳送含圖片的訊息、codex 為 active agent | codex 正常執行，無 `agent_error` |
| claude/gemini 收到圖片正常注入 | 同上、claude/gemini 為 active agent | subprocess args 含 `--add-file` |

## 不在此 Phase 的範圍

- **前端顯示「此 agent 不支援圖片」警告**：Phase 1 可評估是否需要
- **video / audio 檔案支援**：同樣的 `supports_*` 模式，但不在 Phase 0.3 定義
- **圖片轉文字 fallback**（對不支援圖片的 agent 提供 alt text）：Phase 3 範疇
- **gemini 的圖片旗標差異**（若 gemini 不使用 `--add-file` 而是其他旗標）：先假設相同，發現差異後再調整
- **暫存檔清理策略**：`write_temp_images()` 暫存檔的生命週期管理另案處理
