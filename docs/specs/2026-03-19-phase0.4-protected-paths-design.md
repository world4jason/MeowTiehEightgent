> 撰寫日期：2026-03-19
> 版本：v1
> 狀態：待實作
> 關聯 ROADMAP：Phase 0.4

---

## 問題描述

目前 workspace files API 的寫入端點（上傳檔案、儲存檔案內容）沒有路徑驗證：

| 風險 | 情境 | 影響 |
|------|------|------|
| 目錄遍歷（Path Traversal）| agent 或使用者傳入 `../../etc/passwd` 作為 filename | 寫入 workspace 外部的任意路徑 |
| 覆蓋系統設定檔 | agent hallucinate 出 `guide.md` 作為輸出路徑 | 毀掉 agent 人設、workspace 設定 |
| 覆蓋 agent config | filename 為 `../config.json` | 竄改 agent 設定、timeout、cmd |
| 惡意相對路徑 | filename 含 `./` 前綴或多層 `..` | 繞過部分防護 |

這些風險在目前純人工操作時影響有限，但一旦 agent 具備 tool use（Phase 2+）能力後，hallucinated 路徑或被操控的 agent 可能直接觸發寫入操作，風險大幅提升。Phase 0.4 在 tool use 引入前先補上防護。

---

## 設計目標

1. **阻擋路徑遍歷**：任何含 `..`、`/`、`\` 的 filename 一律拒絕
2. **保護系統檔案**：特定受保護檔名（`guide.md` 等）只允許人工透過特定端點修改，agent 寫入一律 403
3. **白名單 > 黑名單**：允許任意合法檔名（英數、dash、underscore、dot），但拒絕危險字元，不嘗試列舉所有壞字元
4. **明確 HTTP 狀態碼**：違規時回傳 `403 Forbidden`，讓 agent tool use 能識別失敗原因
5. **不影響現有合法操作**：使用者正常上傳圖片、文字檔、程式碼不受影響

## 實作細節

### 受保護路徑清單

在 `app.py` 或獨立的 `path_guard.py` 中定義：

```python
# 永遠禁止 agent 寫入的檔名（不含路徑，純檔名比對）
PROTECTED_FILENAMES = frozenset({
    "guide.md",          # workspace agent 人設設定
    "config.json",       # agent-level config
    ".env",              # 環境變數
    "requirements.txt",  # 依賴清單（避免注入惡意套件）
})
```

> `PROTECTED_FILENAMES` 是初始清單，未來可透過 `config.json` 擴充（Phase 0.4 先 hardcode）。

### `validate_filename()` Helper

```python
import re

SAFE_FILENAME_RE = re.compile(r'^[\w\-. ]+$')  # 允許英數、底線、dash、dot、空格
MAX_FILENAME_LENGTH = 255

def validate_filename(filename: str, *, allow_protected: bool = False) -> None:
    """
    驗證 filename 是否安全可寫入。
    不安全時 raise ValueError，呼叫端統一轉成 HTTP 403。

    allow_protected=True：允許寫入 PROTECTED_FILENAMES（僅人工端點使用）
    """
    if not filename:
        raise ValueError("Filename cannot be empty")

    if len(filename) > MAX_FILENAME_LENGTH:
        raise ValueError(f"Filename too long: {len(filename)} chars")

    # 路徑遍歷防護：禁止任何 / \ .. 字元
    if "/" in filename or "\\" in filename:
        raise ValueError(f"Filename must not contain path separators: {filename!r}")

    if ".." in filename:
        raise ValueError(f"Filename must not contain '..': {filename!r}")

    # 安全字元白名單
    if not SAFE_FILENAME_RE.match(filename):
        raise ValueError(f"Filename contains invalid characters: {filename!r}")

    # 受保護檔名
    if not allow_protected and filename in PROTECTED_FILENAMES:
        raise ValueError(f"Filename is protected and cannot be written by agents: {filename!r}")
```

### Endpoint 整合

在所有 workspace 寫入端點呼叫 `validate_filename()`：

**Agent 寫入端點（禁止寫入 protected files）：**
```python
@app.post("/workspace/{workspace_id}/files")
async def upload_workspace_file(
    workspace_id: str,
    filename: str,
    content: UploadFile,
):
    try:
        validate_filename(filename, allow_protected=False)
    except ValueError as e:
        raise HTTPException(status_code=403, detail=str(e))

    # 正常寫入流程...
```

**人工寫入端點（允許寫入 protected files）：**
```python
@app.put("/workspace/{workspace_id}/guide")
async def update_guide(workspace_id: str, body: GuideUpdateRequest):
    # guide.md 由此端點獨立管理，不走通用 validate_filename
    # 此端點本身即為「只有人能觸發」的語意保護
    ...
```

> 若目前後端無區分「agent 寫入」vs「人工寫入」的端點，Phase 0.4 先對所有寫入端點套用 `allow_protected=False`（最嚴格），待後續確認人工操作路徑後再開放特定端點。

### 路徑正規化（防禦縱深）

除 filename 驗證外，實際寫入前對解析出的完整路徑做 `os.path.realpath()` 驗證，確認在 workspace 目錄內：

```python
import os

def safe_workspace_path(workspace_dir: str, filename: str) -> str:
    """
    回傳安全的完整路徑，若解析後路徑不在 workspace_dir 內則 raise ValueError。
    作為 validate_filename() 的縱深防護。
    """
    full_path = os.path.realpath(os.path.join(workspace_dir, filename))
    workspace_real = os.path.realpath(workspace_dir)

    if not full_path.startswith(workspace_real + os.sep) and full_path != workspace_real:
        raise ValueError(f"Path traversal detected: {filename!r} resolves outside workspace")

    return full_path
```

Phase 0.4 不新增 config 欄位，`PROTECTED_FILENAMES` hardcode 在程式碼中。

若未來需要讓 `config.json` 擴充受保護清單，可在 Phase 1+ 新增：
```json
{
  "protected_filenames": ["guide.md", "config.json", ".env"]
}
```

## HTTP 回應規範

| 情境 | HTTP Status | response body |
|------|------------|---------------|
| 路徑遍歷（含 `..` / `/`） | `403 Forbidden` | `{"detail": "Filename must not contain path separators: '../etc/passwd'"}` |
| 受保護檔名 | `403 Forbidden` | `{"detail": "Filename is protected and cannot be written by agents: 'guide.md'"}` |
| 非法字元 | `403 Forbidden` | `{"detail": "Filename contains invalid characters: 'file;rm -rf.txt'"}` |
| 路徑解析後超出 workspace | `403 Forbidden` | `{"detail": "Path traversal detected: ..."}` |
| 正常寫入 | `200 OK` / `201 Created` | 照現有行為 |

## 測試計畫（TDD）

### Unit Tests（`validate_filename()`）

| 測試 | 輸入 | 預期 |
|------|------|------|
| 正常檔名 | `"note.txt"` | 不 raise |
| 含空格的合法檔名 | `"my note.md"` | 不 raise |
| 含數字和 dash | `"report-2026.pdf"` | 不 raise |
| 路徑遍歷（..）| `"../secret.txt"` | raise `ValueError` |
| 路徑遍歷（/）| `"subdir/file.txt"` | raise `ValueError` |
| 路徑遍歷（Windows `\`）| `"subdir\\file.txt"` | raise `ValueError` |
| 雙點不在路徑遍歷 | `"file..txt"` | raise `ValueError`（`..` 視為危險） |
| 受保護檔名 | `"guide.md"` | raise `ValueError` |
| 受保護檔名，allow_protected=True | `"guide.md"` | 不 raise |
| 空字串 | `""` | raise `ValueError` |
| 超長檔名 | 256 字元字串 | raise `ValueError` |
| 含分號（命令注入嘗試）| `"file;rm.txt"` | raise `ValueError`（非法字元） |

### Unit Tests（`safe_workspace_path()`）

| 測試 | 輸入 | 預期 |
|------|------|------|
| 正常檔名在 workspace 內 | `workspace="/tmp/ws"`, `filename="note.txt"` | 回傳 `/tmp/ws/note.txt` |
| Symlink 指向 workspace 外 | filename 對應 symlink 指向 `/etc/` | raise `ValueError` |
| 空 workspace dir | 邊界測試 | 行為明確（不 crash） |

### Integration Tests（Endpoint）

| 測試 | 情境 | 預期 |
|------|------|------|
| 上傳合法檔案 | `POST /workspace/{id}/files` filename=`"note.txt"` | `201 Created` |
| 上傳路徑遍歷 filename | filename=`"../../etc/passwd"` | `403 Forbidden` |
| 上傳 guide.md | filename=`"guide.md"` | `403 Forbidden` |
| 上傳含分號 filename | filename=`"x;y.txt"` | `403 Forbidden` |
